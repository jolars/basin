# Misra1a two-start baseline pilot

This focused pilot ran the four issue-motivating solvers with their constructor
defaults on NIST StRD Misra1a. The [manifest](2026-10-02-misra1a-001.toml)
records the source revision, command, input, and raw-output hash. It is a
development case, not held-out validation. The
[runner](../../../crates/competitor-bench/src/bin/convergence_pilot.rs)
embeds NIST's 14 observations and both starts; its test checks the published
residual sum of squares and analytic Jacobian against finite differences.

Basin minimizes half the residual sum of squares, so the certified cost is
`0.06227569447`. Its rounded certificate places the pilot's observed cost floor
around `2.2e-12`; no cost gap near or below that level should support a rank
order. The table reports the largest relative parameter error and the
independently recomputed cost gap at the returned point. Diagnostic evaluations
are excluded from solver counts.

  | Solver      | Start 1: stop, relative parameter error, cost gap | Start 2: stop, relative parameter error, cost gap |
  | ----------- | ------------------------------------------------- | ------------------------------------------------- |
  | Nelder–Mead | `MaxIter`, `2.53e-9`, `2.20e-12`                  | `MaxIter`, `4.55e-9`, `2.20e-12`                  |
  | L-BFGS-B    | `MaxIter`, `2.07e-4`, `1.28e-6`                   | `MaxIter`, `3.62e-5`, `3.91e-8`                   |
  | LM          | `NumericalNoProgress`, `4.14e-10`, `2.20e-12`     | `NumericalNoProgress`, `5.04e-11`, `2.20e-12`     |
  | TRF         | `SolverFailed`, `3.65e-10`, `2.20e-12`            | `SolverConverged`, `7.97e-12`, `2.20e-12`         |

Five of the six runs with relative parameter error below `1e-8` ended without
`SolverConverged`. This reproduces the **classification pattern** described in
[issue #109](https://github.com/jolars/basin/issues/109) on one public NIST
case, but it does not reproduce that issue's 27-case counts. L-BFGS-B did not
reach the same parameter accuracy in 500 iterations. Its outcome is a quality
and work question, not just a termination-label question. This pilot cannot
separate an overstrict stop from line-search behavior or curvature history.

The cost and gradient counters are different callback categories from LM/TRF's
residual and Jacobian counters; their numbers should not be summed as equal
physical work. The runner does not yet record a full boundary trace, all passing
stop criteria, elapsed time, or callback-level fused work. Those are step 5
harness requirements. Do not select any new default from this pilot.

Next: review the [protocol](../protocol.md), add stage-aware tracing and
physical callback accounting, then compare current and reference candidates on
additional case families. Check TRF's first-start inner failure path and
L-BFGS-B's slower first-start trajectory before assigning a cause.
