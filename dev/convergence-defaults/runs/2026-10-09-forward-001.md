# Forward-difference stopping configuration, 2026-10-09

Purpose: resolve the analytic forward-difference fixture's stopping mismatch
with an explicit solver setting. This validates a configuration, not a new
default. The [manifest](2026-10-09-forward-001.toml) was committed before
execution at `33c43f0`; source was committed at `a73c8a5`. Both configurations
use the same release binary. Independent checks passed for 18 cases and 38 CSV
files, including eight unchanged control fixtures and identical forward calls
and published points before stopping.

## Cause and configuration

The fixture is `f(x) = 0.5*((x0-1)^2 + (x1+2)^2)`, with start `(4,3)` and bounds
`[-8,8]`. At its exact minimum `(1,-2)`, the default forward stencil uses
representable steps `h = (2^-26, 2^-25)`. Its gradient is `(2^-27, 2^-26)`, even
though the analytic gradient is zero. The infinity norm `1.4901161193847656e-8`
exceeds bounded L-BFGS's default `1e-10` threshold. The strict run reaches the
minimum, then attempts a line search that fails.

For this fixture, configure
`Lbfgs::new().with_absolute_projected_gradient_tolerance(1e-7)` with the forward
adapter. The probe accepts `--forward-tolerance 1e-7` and keeps the strict
configuration when that option is absent. Rustdoc for L-BFGS and both
finite-difference adapters explains derivative error, scaling, and precision;
the L-BFGS example compiles and verifies convergence and the exact return.

and all published rows before stopping are identical. The other eight fixtures
have identical traces, counts, and outcomes between runs; elapsed time is
excluded from that comparison. Central differences still converge with `1e-10`,
using 15 physical calls.

Exploratory assertions that merely multiplied this tolerance by extreme
objective scales did not establish comparable solve accuracy: the `1e-8`
multiplier produced a native `f32` line-search failure and a failed `f64`
parameter-accuracy assertion. The final scaling checks therefore cover
derivative bias at the exact witness for multipliers `1e-8`, `1`, and `1e8`;
solve assertions cover the unit-scale fixture. No general scale-invariance or
tolerance recommendation follows. Choosing a threshold above witness bias alone
does not establish solve accuracy on an arbitrary problem.

The fix makes the supported fixture configuration explicit and guards its
behavior. No production numerical safeguard or general solver default changed.
NIST model validation, independent precision eligibility, and the full LM/TRF
pilot remain the next step before calibration.
